    capture_thought

    Saves a note or thought to Cortex. On every capture the server runs two operations automatically:

    1. Embedding — generates a 4096-dimensional vector (qwen3-embedding via Ollama) and stores it in the entries table with pgvector for semantic retrieval.
    2. Metadata extraction — calls an LLM (via extractMetadata) to classify the thought and pull out structured fields: type, topics, people, and action_items.

    Deduplication is handled server-side using a SHA-256 fingerprint of the normalised content. Re-submitting identical content returns duplicate: true and does not create a new row.

    Parameters

    Name Type Required Default Description
    content string ✅ Yes — The thought to capture — a clear, self-contained statement

    Write content as a single, self-contained statement. Fragmentary phrases yield weaker metadata extraction and lower-quality embeddings.

    Returns

    A text response containing:

    Field Description
    id UUID of the created or existing entry
    type LLM-assigned content type (e.g. observation, task, idea)
    topics List of topic tags extracted from the content
    people People mentioned in the thought
    action_items Any action items detected
    duplicate true if identical content was already stored; the existing entry is returned

    Usage examples

    Capturing a decision

    {
  "name": "capture_thought",
  "arguments": {
    "content": "Decided to migrate the auth layer to Clerk before the Q3 launch; keeps us off the OAuth maintenance path."
  }
}

    Capturing a task

    {
  "name": "capture_thought",
  "arguments": {
    "content": "Follow up with Jordan about the infrastructure budget by end of week."
  }
}

    Capturing an observation

    {
  "name": "capture_thought",
  "arguments": {
    "content": "Users consistently abandon the onboarding flow at step 4 — the permissions prompt is the likely friction point."
  }
}

    Deduplication behaviour

    If you submit the same content a second time, the upsert_entry RPC detects the fingerprint match and returns the existing entry unchanged. The response will include duplicate: true. No new row is written.

    Implementation notes

    • Embedding and metadata extraction run in parallel before the database write, so latency scales with the slower of the two (typically the LLM metadata call).
    • The ingestion source is recorded as 'mcp' in the entries table, which allows thought-only search tools to distinguish captured notes from wiki pages.
    • The tool is backed by the shared captureThought() helper in src/server/lib/capture.ts, used by the HTTP REST API, the Discord bot, and this MCP tool — all three paths produce identical entries.

    Related tools

    • search_thoughts — find previously captured thoughts by semantic similarity
    • list_thoughts — browse thoughts chronologically with optional filters
    • thought_stats — aggregate counts, type breakdown, top topics and people
