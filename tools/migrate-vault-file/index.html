    migrate_vault_file

    Copies a file from MainVault into the WikiVault raw/ folder, applies standardised frontmatter, strips Dataview blocks, generates vector embeddings, and indexes the result in Supabase. The original MainVault source file is never modified.

    Use this tool during a one-time vault migration or to import individual articles on demand. It is scoped to raw_* page types only — for managed wiki entries (wiki_person, wiki_project, etc.), use write_wiki_page instead.

    Parameters

    Parameter Type Required Default Description
    source_path string Yes — Absolute path to the MainVault source file, e.g. /Users/me/MainVault/Articles/transformer-paper.md
    target_type string (enum) Yes — Destination subfolder type. One of: raw_article, raw_book, raw_daily, raw_attachment
    force boolean No false If true, overwrites an existing WikiVault file at the computed target path

    target_type values

    Value Description
    raw_article An article or essay imported from MainVault
    raw_book A book note or summary
    raw_daily A daily note
    raw_attachment An attachment or supporting file

    The exact destination path within raw/ is determined by the server based on target_type.

    Returns

    On success, returns a confirmation that includes the relative path of the newly created WikiVault file and a summary of the transformations applied (frontmatter added, Dataview blocks stripped, embedding stored, Supabase index entry created). The exact response structure is server-defined.

    Behaviour notes

    • Non-destructive: the original MainVault file is never modified or deleted.
    • Dataview stripping: Dataview query blocks in the source are removed before the file is written to WikiVault.
    • Frontmatter: standardised frontmatter is added to the WikiVault copy automatically; you do not need to supply it.
    • Embedding + indexing: the imported file is embedded and indexed in Supabase so it is immediately searchable via search_wiki and search_all.
    • Overwrite guard: if the target file already exists in WikiVault and force is false, the tool will not overwrite it. Set force: true to replace an existing file.

    Usage examples

    Import a single article

    {
  "name": "migrate_vault_file",
  "arguments": {
    "source_path": "/Users/me/MainVault/Articles/transformer-paper.md",
    "target_type": "raw_article",
    "force": false
  }
}

    Re-import a book note, replacing any existing copy

    {
  "name": "migrate_vault_file",
  "arguments": {
    "source_path": "/Users/me/MainVault/Books/thinking-fast-and-slow.md",
    "target_type": "raw_book",
    "force": true
  }
}

    Import a daily note

    {
  "name": "migrate_vault_file",
  "arguments": {
    "source_path": "/Users/me/MainVault/Daily/2024-01-15.md",
    "target_type": "raw_daily"
  }
}

    When to use this tool

    • Bulk migration: iterating over MainVault files and importing them into WikiVault in a single pass.
    • On-demand import: a specific source file needs to be made searchable in WikiVault without manually rewriting it.
    • Re-indexing: a previously imported file has changed in MainVault and needs to be reimported with force: true.

    Do not use migrate_vault_file for: - Creating or updating managed wiki pages — use write_wiki_page for those. - Files you have already written directly into WikiVault via write_wiki_page.
