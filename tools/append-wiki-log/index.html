    append_wiki_log

    Write a one-line timestamped entry to log.md in the WikiVault root. Call this after every write_wiki_page invocation or any other significant wiki decision to maintain a durable audit trail.

    When to use

    • Immediately after write_wiki_page creates or overwrites a page.
    • After any significant decision about WikiVault structure or content (e.g. archiving a page, merging duplicates, deciding not to update a page).
    • Whenever you want a permanent, human-readable record of an action taken in the vault.

    append_wiki_log is a pure filesystem append to log.md — it does not call any embedding or database services.

    Parameters

    Parameter Type Required Default Description
    file_path string ✅ Yes — Relative path of the WikiVault page that was acted on (e.g. wiki/people/Alice-Smith.md)
    summary string ✅ Yes — One-line description of what was done. Maximum 200 characters.

    Parameter notes

    • file_path — Use a path relative to the WikiVault root, matching the path returned by write_wiki_page or list_wiki_pages. Do not use absolute paths.
    • summary — Keep it concise and action-oriented (e.g. "Created page from captured thoughts about Q2 planning"). The 200-character limit is enforced.

    Log line format

    Each call appends exactly one line to log.md:

    ISO-timestamp | tool | file_path | summary

    Example:

    2026-05-25T04:28:30.000Z | append_wiki_log | wiki/people/Alice-Smith.md | Created page synthesising three captured thoughts about Alice's role in Project Phoenix

    The log.md file accumulates entries chronologically and is never truncated by this tool.

    Returns

    A confirmation message indicating the log entry was written, including the timestamp and the path to log.md.

    On failure (e.g. WikiVault directory not found, write permission denied), the tool returns an error message with isError: true.

    Usage examples

    After writing a new wiki page

    {
  "tool": "write_wiki_page",
  "params": {
    "title": "Alice Smith",
    "type": "wiki_person",
    "body": "## Overview\n\nAlice is the engineering lead for Project Phoenix..."
  }
}

    {
  "tool": "append_wiki_log",
  "params": {
    "file_path": "wiki/people/Alice-Smith.md",
    "summary": "Created person page for Alice Smith from three captured thoughts"
  }
}

    After updating an existing page

    {
  "tool": "append_wiki_log",
  "params": {
    "file_path": "wiki/projects/Project-Phoenix.md",
    "summary": "Added Q2 milestone section based on decision captured 2026-05-24"
  }
}

    After a significant decision (no write)

    {
  "tool": "append_wiki_log",
  "params": {
    "file_path": "wiki/concepts/Technical-Debt.md",
    "summary": "Reviewed page — no update needed; content still accurate as of today"
  }
}

    Recommended workflow

    Always pair write_wiki_page with append_wiki_log:

    1. Call read_wiki_page to check whether the page exists.
    2. Call write_wiki_page to create or update the page.
    3. Call append_wiki_log immediately after with the relative file path and a concise summary.

    This sequence ensures every write has a corresponding audit entry and the log stays consistent with the vault's actual state.

    Related tools

    Tool Relationship
    write_wiki_page The primary trigger for calling append_wiki_log
    read_wiki_page Read before writing; then log after writing
    list_wiki_pages Use to confirm the relative file_path to log
