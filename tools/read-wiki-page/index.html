    read_wiki_page

    Read the full content and frontmatter of a WikiVault page. This is a pure filesystem operation — no database queries or embedding calls are made.

    Required before writing. Always call read_wiki_page before write_wiki_page when a page may already exist. write_wiki_page overwrites the file; reading first ensures you preserve existing content and frontmatter fields.

    Parameters

    Parameter Type Required Default Description
    identifier string Yes — Page title (e.g. "Alice Smith") or relative file path (e.g. "wiki/people/Alice-Smith.md")

    Identifier resolution

    The tool selects its lookup strategy based on the value of identifier:

    • Relative file path — if identifier contains a /, the file is read directly from the WikiVault root. Example: "wiki/people/Alice-Smith.md".
    • Title — if identifier contains no /, the tool scans the WikiVault filesystem via listWikiPages and matches against page titles case-insensitively. Example: "alice smith" will match a page titled "Alice Smith".

    Use the file path form when you already know the exact location (faster, unambiguous). Use the title form when you have only the human-readable name.

    Returns

    A formatted text block containing:

    1. All frontmatter fields (title, type, tags, status, created, updated, wikilinks, sources, etc.)
    2. The full markdown body

    Returns an error message if no matching page is found.

    Usage examples

    Read by title

    {
  "name": "read_wiki_page",
  "arguments": {
    "identifier": "Alice Smith"
  }
}

    Read by relative file path

    {
  "name": "read_wiki_page",
  "arguments": {
    "identifier": "wiki/people/Alice-Smith.md"
  }
}

    Case-insensitive title lookup

    {
  "name": "read_wiki_page",
  "arguments": {
    "identifier": "machine learning"
  }
}

    This will match a page titled "Machine Learning", "machine learning", or any other capitalisation variant.

    Read-before-write pattern

    The canonical update workflow:

    1. Call read_wiki_page with the page title or path.
    2. Inspect the returned frontmatter and body.
    3. Merge your changes into the existing content.
    4. Call write_wiki_page with the complete updated body and all preserved fields.
    5. Call append_wiki_log to record the action.

    Skipping step 1 risks clobbering existing data — frontmatter fields like created, wikilinks, cortex_ids, and page_sources are not automatically carried forward by write_wiki_page unless you supply them explicitly.

    Implementation notes

    • Implemented in src/server/routes/mcp.ts; filesystem operations are handled by src/server/lib/wiki.ts (readWikiPage, listWikiPages).
    • Title lookup iterates the result of listWikiPages (a directory scan) and compares titles case-insensitively. Only the frontmatter title field is matched — not filenames.
    • No Supabase or Ollama calls are made; the tool works even if the database or inference service is unavailable.
    • The WikiVault root is configured via the WIKI_VAULT_PATH environment variable (default: ~/Documents/Obsidian/WikiVault/).

    Related tools

    Tool When to use
    write_wiki_page Create or overwrite a page — always read first
    search_wiki Find pages by meaning when you don't know the exact title
    list_wiki_pages Browse all pages of a given type
    append_wiki_log Record an action after writing
