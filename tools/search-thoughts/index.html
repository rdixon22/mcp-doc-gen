    search_thoughts

    Search captured thoughts by meaning using semantic similarity. Unlike keyword search, this tool finds notes that are conceptually related to your query even when the exact words differ.

    Scope: thoughts only (sources: web, discord, mcp, api). Wiki pages are excluded. Use search_all for combined results across both thoughts and wiki, or search_wiki for wiki pages only.

    Parameters

    Parameter Type Required Default Description
    query string Yes — What to search for
    limit number No 10 Maximum number of results to return
    threshold number No 0.5 Minimum similarity score (0–1); results below this are excluded

    Threshold guidance

    Goal Suggested threshold
    High precision, exact topic 0.7 – 0.8
    Balanced (default) 0.5
    Broad recall, uncertain phrasing 0.3 – 0.4

    Lower the threshold when you are unsure how a thought was originally phrased or when the concept may have been captured tangentially. Raise it to filter out loosely related results.

    How it works

    The query string is embedded using the configured Ollama embedding model. The resulting vector is compared against stored thought embeddings using cosine similarity via the Supabase match_entries RPC, filtered to non-wiki sources. Only results meeting or exceeding threshold are returned, ranked from most to least similar, up to limit results.

    Returns

    A ranked list of matching thoughts. Each result includes:

    • Date — when the thought was captured
    • Type — the classified thought type (e.g. observation, task, idea)
    • Topics — extracted topic tags
    • People — mentioned individuals
    • Action items — any action items extracted from the thought
    • Content — the full text of the thought

    Returns an empty list when no results meet the threshold. Does not return thoughts from wiki pages regardless of threshold.

    Usage examples

    Basic search

    {
  "name": "search_thoughts",
  "arguments": {
    "query": "product roadmap priorities for Q3"
  }
}

    High-precision search with fewer results

    {
  "name": "search_thoughts",
  "arguments": {
    "query": "decision to migrate to microservices",
    "limit": 5,
    "threshold": 0.72
  }
}

    Broad recall when phrasing is uncertain

    {
  "name": "search_thoughts",
  "arguments": {
    "query": "meeting with Alice about the budget",
    "limit": 20,
    "threshold": 0.35
  }
}

    When to use this tool

    • The user asks what they previously noted about a topic, person, or event.
    • You want to surface relevant context before responding to a question.
    • You need to check whether a thought already exists before capturing a duplicate.

    Prefer search_all when you do not know whether the relevant content was captured as a thought or written as a wiki page.

    Prefer list_thoughts when you want chronological browsing with structured filters (type, topic, person, date range) rather than semantic ranking.
