    search_all

    Perform a single semantic search across all entries in Cortex: captured thoughts (from web, Discord, MCP, and API sources) and WikiVault pages together. Results are ranked by relevance and labelled by source so you can tell at a glance whether a hit came from a thought or a wiki page.

    Use search_all when you are unsure whether the information you are looking for was saved as a quick note or as a structured wiki entry. For narrower queries, prefer search_thoughts or search_wiki.

    Parameters

    Parameter Type Required Default Description
    query string yes — The search query. Embedded with qwen3-embedding and compared against all entries using cosine similarity.
    limit number no 15 Maximum number of results to return.
    threshold number no 0.45 Minimum cosine similarity score (0–1). Lower than other search tools to maximise recall across both corpora.

    Threshold note

    The default threshold of 0.45 is intentionally more permissive than search_thoughts (0.5) and search_wiki (0.5). This trades precision for recall, surfacing relevant entries that might otherwise be missed when you are exploring unfamiliar territory. Raise it toward 0.6–0.7 if you are getting too many loosely-related results.

    Returns

    A text response listing matched entries in ranked order. Each entry includes:

    • Source label — [thought] with a subtype (e.g. idea, task) or [wiki:page_type] (e.g. [wiki:wiki_person], [wiki:wiki_concept])
    • Title or date — wiki page title, or capture timestamp for thoughts
    • Tags — topic tags attached to the entry
    • Excerpt — up to 300 characters of the entry body
    • Similarity score — the cosine similarity value

    Returns an empty result set (not an error) when no entries exceed the threshold.

    How it works

    search_all embeds query using Ollama (qwen3-embedding, 4096-d vectors) and calls the Supabase match_entries RPC with source_filter: null and no page-type filter. This scans the unified entries table across all source values — thoughts captured from any ingestion path and wiki pages indexed with source='wiki'. Results are sorted by cosine distance and truncated to limit.

    Usage examples

    Broadest possible recall

    {
  "name": "search_all",
  "arguments": {
    "query": "machine learning model deployment"
  }
}

    Returns up to 15 results from both thoughts and wiki pages, labelled by source.

    Increase result count and tighten threshold

    {
  "name": "search_all",
  "arguments": {
    "query": "Alice's feedback on the Q3 roadmap",
    "limit": 25,
    "threshold": 0.55
  }
}

    Returns up to 25 results with a higher similarity bar, filtering out loosely-related entries.

    Exploring an unfamiliar topic

    {
  "name": "search_all",
  "arguments": {
    "query": "distributed tracing observability",
    "limit": 20,
    "threshold": 0.4
  }
}

    Drops the threshold below the default to surface even loosely-related notes and wiki pages when you are not sure how the topic was originally framed.

    When to use search_all vs. other search tools

    Situation Recommended tool
    Not sure if info is in a thought or wiki page search_all
    Definitely looking in captured notes only search_thoughts
    Definitely looking in wiki pages only search_wiki
    Looking in past AI chat conversations search_messages
    Know the exact wiki page title read_wiki_page
    Want to browse by type chronologically list_thoughts or list_wiki_pages
