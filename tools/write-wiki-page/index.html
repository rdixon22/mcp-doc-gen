    write_wiki_page

    Creates or overwrites a WikiVault page. Used to maintain LLM-curated wiki entries for people, projects, concepts, areas, topics, and raw imported content.

    ⚠ Read before you write. Always call read_wiki_page first if the page may already exist. This tool performs a full overwrite — calling it without reading first will silently discard existing content.

    What happens on write

    1. A kebab-case file path is derived from title and type (e.g. wiki/people/Alice-Smith.md).
    2. writeWikiPage merges the call with any existing frontmatter: created is preserved, updated is bumped to now, and [[wikilinks]] in the body are automatically extracted and stored in the frontmatter wikilinks[] array.
    3. The page is written to the WikiVault filesystem with auto-generated YAML frontmatter. Do not include frontmatter in body.
    4. The body is embedded via Ollama (qwen3-embedding) and upserted into Supabase via the upsert_entry RPC (source='wiki').
    5. For new pages, index.md is rebuilt. Every write should be followed by append_wiki_log to maintain the audit trail.

    Parameters

    Parameter Type Required Default Description
    title string ✅ — Human-readable page title, e.g. "Alice Smith". Used to derive the file name.
    type string (enum) ✅ — Page type — determines the destination subfolder. See Page types below.
    body string ✅ — Full markdown body. Do not include YAML frontmatter — it is generated automatically.
    tags string[] ❌ [] Topic tags in lowercase-kebab format, e.g. ["machine-learning", "nlp"].
    page_sources string[] ❌ [] Source URLs, raw/ file paths, or entry UUIDs that this page was derived from.
    cortex_ids string[] ❌ [] UUIDs from the Supabase entries table that this wiki page synthesises. Enables traceability back to captured thoughts.
    status string (enum) ❌ "active" Page lifecycle status: active, archived, or stub.

    Page types

    Value Destination subfolder Typical use
    wiki_person wiki/people/ Person profiles
    wiki_project wiki/projects/ Project pages
    wiki_concept wiki/concepts/ Definitions, ideas
    wiki_area wiki/areas/ Life/work areas
    wiki_topic wiki/topics/ Topic overviews
    raw_article raw/articles/ Imported articles
    raw_book raw/books/ Imported book notes
    raw_daily raw/daily/ Daily notes
    raw_attachment raw/attachments/ Misc imported files

    Returns

    A text response confirming: - The file path the page was written to - Whether it was created new or updated - The number of wikilinks extracted from the body - Confirmation of Supabase indexing

    On error, isError: true is set and the text describes the failure (e.g. invalid type, filesystem write error, embedding failure).

    Usage examples

    Create a new person page

    {
  "name": "write_wiki_page",
  "arguments": {
    "title": "Alice Smith",
    "type": "wiki_person",
    "body": "## Overview\n\nAlice is an ML researcher at DeepMind focused on [[Reinforcement Learning]].\n\n## Notes\n\n- Met at NeurIPS 2024\n- Working on reward modelling for [[RLHF]]",
    "tags": ["ml", "reinforcement-learning", "deepmind"],
    "status": "active"
  }
}

    Update an existing page (read-first pattern)

    // Step 1 — always read first
{
  "name": "read_wiki_page",
  "arguments": {
    "identifier": "Alice Smith"
  }
}

// Step 2 — write with updated content
{
  "name": "write_wiki_page",
  "arguments": {
    "title": "Alice Smith",
    "type": "wiki_person",
    "body": "## Overview\n\nAlice is an ML researcher at DeepMind focused on [[Reinforcement Learning]].\n\n## Notes\n\n- Met at NeurIPS 2024\n- Working on reward modelling for [[RLHF]]\n- Joined as advisor on [[Project Athena]] in Jan 2025",
    "tags": ["ml", "reinforcement-learning", "deepmind"],
    "status": "active"
  }
}

// Step 3 — log the action
{
  "name": "append_wiki_log",
  "arguments": {
    "file_path": "wiki/people/Alice-Smith.md",
    "summary": "Added Project Athena advisor note"
  }
}

    Create a project stub with source tracing

    {
  "name": "write_wiki_page",
  "arguments": {
    "title": "Project Athena",
    "type": "wiki_project",
    "body": "## Status\n\nEarly-stage. See [[Alice Smith]] for context.\n\n## Goals\n\nTBD.",
    "tags": ["active-project"],
    "cortex_ids": ["3f2a1b4c-8d9e-4f1a-b2c3-d4e5f6a7b8c9"],
    "status": "stub"
  }
}

    Wikilinks

    Any [[Page Title]] reference in body is automatically extracted and written to the frontmatter wikilinks array. This enables forward-link tracking across the vault. You do not need to declare wikilinks separately — just write them naturally in the body.

    Frontmatter generated automatically

    The tool builds YAML frontmatter from your parameters plus system fields. Example output for a person page:

    ---
title: Alice Smith
type: wiki_person
status: active
tags:
  - ml
  - reinforcement-learning
  - deepmind
wikilinks:
  - Reinforcement Learning
  - RLHF
page_sources: []
cortex_ids: []
created: 2025-01-15T10:23:00.000Z
updated: 2025-04-02T14:05:00.000Z
---

    Never include a frontmatter block in your body argument. If you do, it will appear as literal text in the rendered page.

    Related tools

    Tool When to use
    read_wiki_page Always call before writing if the page may exist
    append_wiki_log Call after every write to maintain the audit trail
    search_wiki Find a page when you don't know the exact title
    list_wiki_pages Enumerate pages by type to check existence
    migrate_vault_file Import a file from MainVault instead of writing from scratch
