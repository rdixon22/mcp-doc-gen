    write_wiki_page

    Creates a new WikiVault page or fully overwrites an existing one. On write, Cortex automatically builds YAML frontmatter, generates vector embeddings, and indexes the page in Supabase — you only provide the markdown body.

    ⚠ Read before you write. This tool performs a full overwrite. Always call read_wiki_page first if the page may already exist. Calling write_wiki_page without reading first risks permanently discarding content.

    Parameters

    Parameter Type Required Default Description
    title string ✅ Yes — Human-readable page title, e.g. "Alice Smith". Used to derive the filename and frontmatter.
    type string (enum) ✅ Yes — Page type — determines which WikiVault subfolder the file is placed in. See Page Types below.
    body string ✅ Yes — Full markdown content of the page. Do not include frontmatter — it is generated automatically.
    tags string[] No [] Topic tags in lowercase-kebab format, e.g. ["engineering", "q4-planning"].
    page_sources string[] No [] Provenance references: source URLs, raw/ file paths, or Cortex entry UUIDs.
    cortex_ids string[] No [] Supabase entries table UUIDs of the captured thoughts this page synthesises. Links the wiki page back to its source thoughts.
    status string (enum) No "active" Page lifecycle status: active, archived, or stub.

    Page Types

    The type value determines the destination subfolder within WikiVault:

    Value Subfolder Intended use
    wiki_person wiki/people/ Individual people — colleagues, contacts, authors
    wiki_project wiki/projects/ Projects and initiatives
    wiki_concept wiki/concepts/ Ideas, frameworks, and mental models
    wiki_area wiki/areas/ Ongoing areas of responsibility
    wiki_topic wiki/topics/ Broad topic summaries
    raw_article raw/articles/ Imported articles (prefer migrate_vault_file for MainVault imports)
    raw_book raw/books/ Book notes and summaries
    raw_daily raw/daily/ Daily notes
    raw_attachment raw/attachments/ Supporting attachments

    Returns

    A confirmation object containing:

    • file_path — the relative path of the written file within WikiVault (e.g. wiki/people/Alice-Smith.md)
    • frontmatter — the generated YAML frontmatter applied to the file
    • status — success confirmation and indexing status

    Usage Examples

    Create a new person page (safe — page is known not to exist)

    {
  "title": "Alice Smith",
  "type": "wiki_person",
  "body": "## Role\n\nEngineering Lead on the Platform team.\n\n## Notes\n\n- Prefers async communication\n- Leading the Q4 reliability push\n\n## Action Items\n\n- [ ] Share architecture doc by Friday",
  "tags": ["engineering", "leadership", "platform"],
  "status": "active"
}

    Update an existing page (read-first pattern)

    Always read before writing to an existing page:

    // Step 1 — read_wiki_page
{
  "identifier": "Alice Smith"
}

// Step 2 — write_wiki_page (with merged/updated body)
{
  "title": "Alice Smith",
  "type": "wiki_person",
  "body": "## Role\n\nEngineering Lead on the Platform team.\n\n## Notes\n\n- Prefers async communication\n- Leading the Q4 reliability push\n- Joined the architecture review board (updated 2026-05)\n\n## Action Items\n\n- [x] Share architecture doc by Friday\n- [ ] Review onboarding proposal",
  "tags": ["engineering", "leadership", "platform"],
  "cortex_ids": ["3f8a1c2d-4e5b-6789-abcd-ef0123456789"],
  "status": "active"
}

    Create a concept stub for later expansion

    {
  "title": "Second Brain",
  "type": "wiki_concept",
  "body": "A system for capturing, organising, and retrieving personal knowledge.\n\n*Stub — to be expanded.*",
  "tags": ["knowledge-management", "productivity"],
  "status": "stub"
}

    Synthesise multiple captured thoughts into a project page

    {
  "title": "Project Nightingale",
  "type": "wiki_project",
  "body": "## Overview\n\nInternal data pipeline modernisation project.\n\n## Decisions\n\n- Migrating from Airflow to Prefect\n- Target completion: Q3 2026\n\n## Key People\n\n- [[Alice Smith]] — Tech Lead\n- [[Bob Torres]] — PM",
  "tags": ["data-engineering", "infrastructure", "q3-2026"],
  "cortex_ids": [
    "1a2b3c4d-0000-0000-0000-111111111111",
    "5e6f7a8b-0000-0000-0000-222222222222"
  ],
  "page_sources": ["raw/articles/prefect-migration-notes.md"],
  "status": "active"
}

    Protocol Notes

    1. Always call read_wiki_page first if there is any chance the page exists. write_wiki_page is a full overwrite — it does not merge or patch.
    2. Do not include frontmatter in body. Cortex builds it automatically from title, type, tags, status, and other parameters. Adding frontmatter to the body will result in duplicate or malformed YAML.
    3. After every write, call append_wiki_log with the file path and a one-line summary of what changed. This maintains the audit trail in log.md.
    4. Use cortex_ids to link synthesised wiki pages back to the source captured thoughts. This preserves provenance and makes the knowledge graph navigable.
    5. Tags must be lowercase-kebab — e.g. machine-learning, not Machine Learning or MachineLearning.
