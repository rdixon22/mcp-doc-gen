    Setup Guide

    Cortex requires four external services to be running before the server starts: Ollama (local LLM inference), Supabase (Postgres + pgvector, running in Docker), a WikiVault directory on the filesystem, and optionally a Discord bot token. Follow the steps in order.

    1. Prerequisites

    Requirement Version / Notes
    Node.js LTS recommended; install via nvm
    npm Bundled with Node.js
    Docker + Docker Compose Required for local Supabase
    Supabase CLI npm install -g supabase
    Ollama ollama.ai — must be running locally
    Git To clone the repo

    Clone the repository and install dependencies:

    git clone https://github.com/your-org/cortex.git
cd cortex
npm install

    2. Start Ollama and Pull Models

    Cortex needs three Ollama models. The embedding model is mandatory; the others default to the values below but can be overridden via env vars.

    # Start the Ollama daemon (runs on http://localhost:11434 by default)
ollama serve

# Required: 4096-dimensional embedding model
ollama pull qwen3-embedding

# Required: chat/assistant model
ollama pull glm-4.7-flash

# Optional: cloud-routed metadata extraction model
ollama pull glm-5:cloud

    If Ollama is on a different host or port, set OLLAMA_HOST in your .env (step 4).

    3. Start Local Supabase and Apply Migrations

    # Start Supabase in Docker (first run downloads images — allow a few minutes)
supabase start

    Supabase surfaces a Studio dashboard at http://localhost:8000. The CLI prints the local API URL and service_role key — you will need both for your .env.

    Apply migrations

    Open the Supabase SQL editor (Studio → SQL Editor) and run the migration files in order:

    supabase/migrations/001_*.sql   # conversations + messages tables
supabase/migrations/002_*.sql
supabase/migrations/003_*.sql
supabase/migrations/004_entries.sql   # ← most important

    004_entries.sql creates:

    • entries table — unified store for thoughts and wiki pages, with a vector(4096) embedding column, JSONB metadata, and wiki-specific columns (file_path, title, page_type, tags, wikilinks, page_sources, cortex_ids).
    • upsert_entry RPC — SHA-256 content fingerprint deduplication; returns duplicate: true if the content already exists.
    • match_entries RPC — pgvector cosine similarity search with optional source and JSONB filters.

    The messages table (for chat history) and match_messages RPC are created by the earlier migration files.

    4. Environment Variables

    Copy the example file and fill in each value:

    cp .env.example .env

    Required

    Variable Description Example
    SUPABASE_URL Local Supabase API URL (from supabase start output) http://localhost:54321
    SUPABASE_SERVICE_ROLE_KEY Service-role JWT (Studio → Settings → API) eyJhbGci...

    Model configuration (optional — defaults shown)

    Variable Default Description
    OLLAMA_HOST http://localhost:11434 Ollama base URL
    EMBEDDING_MODEL qwen3-embedding Model used for all vector embeddings
    CHAT_MODEL glm-4.7-flash Model used for chat and Q&A
    METADATA_MODEL glm-5:cloud Model used for thought metadata extraction

    MCP access (optional but recommended for HTTP transport)

    Variable Description How to generate
    MCP_ACCESS_KEY Bearer token required by HTTP MCP clients openssl rand -hex 16

    Leave MCP_ACCESS_KEY empty to disable authentication entirely (useful for local-only setups).

    WikiVault paths (optional — defaults shown)

    Variable Default Description
    WIKI_VAULT_PATH ~/Documents/Obsidian/WikiVault Root directory of the WikiVault
    MAIN_VAULT_PATH ~/Documents/Obsidian/MainVault Source path for the one-time migration tool

    Discord integration (optional)

    Variable Description
    DISCORD_BOT_TOKEN Bot token from the Discord Developer Portal
    DISCORD_CAPTURE_CHANNEL_ID Channel ID where messages are auto-captured as thoughts

    Leave both unset to disable the Discord bot entirely — initDiscordBot() is a no-op when DISCORD_BOT_TOKEN is absent.

    5. Create the WikiVault Directory Structure

    The WikiVault is a plain directory of markdown files. Create it manually before starting the server:

    WIKI_VAULT_PATH="${WIKI_VAULT_PATH:-$HOME/Documents/Obsidian/WikiVault}"

mkdir -p "$WIKI_VAULT_PATH/wiki/people"
mkdir -p "$WIKI_VAULT_PATH/wiki/projects"
mkdir -p "$WIKI_VAULT_PATH/wiki/concepts"
mkdir -p "$WIKI_VAULT_PATH/wiki/areas"
mkdir -p "$WIKI_VAULT_PATH/wiki/topics"
mkdir -p "$WIKI_VAULT_PATH/raw/articles"
mkdir -p "$WIKI_VAULT_PATH/raw/books"
mkdir -p "$WIKI_VAULT_PATH/raw/daily"
mkdir -p "$WIKI_VAULT_PATH/raw/attachments"

# Create required stub files
touch "$WIKI_VAULT_PATH/SCHEMA.md"
touch "$WIKI_VAULT_PATH/index.md"
touch "$WIKI_VAULT_PATH/log.md"

    index.md is rebuilt automatically by write_wiki_page. log.md is appended by append_wiki_log and tracks every significant wiki action. SCHEMA.md is reserved for documentation of your vault's conventions — populate it as you like.

    6. Start the Server

    Development (frontend + backend together)

    npm run dev

    This uses concurrently to launch:

    • Vite frontend at http://localhost:5173 (proxies /api to the backend)
    • Express + MCP backend at http://localhost:3001

    The MCP Streamable HTTP endpoint is available at http://localhost:3001/mcp.

    Verify the setup

    # Check Supabase connectivity
curl http://localhost:3001/api/db

# List available Ollama models
curl http://localhost:3001/api/models

    7. Connect an MCP Client

    Claude Desktop (stdio transport)

    Edit ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) — all paths must be absolute:

    {
  "mcpServers": {
    "cortex": {
      "command": "node",
      "args": [
        "--env-file=/absolute/path/to/cortex/.env",
        "--import=/absolute/path/to/cortex/node_modules/tsx/dist/esm/index.cjs",
        "/absolute/path/to/cortex/src/server/mcp-stdio.ts"
      ]
    }
  }
}

    Claude Desktop spawns src/server/mcp-stdio.ts as a subprocess connected via stdio. This file creates a CortexMCPServer via the same createCortexServer() factory used by the HTTP endpoint, so all 12 tools are available identically over both transports.

    HTTP MCP clients (Cursor, custom agents)

    Connect to:

    http://localhost:3001/mcp?key=<MCP_ACCESS_KEY>

    Or pass the key as a request header:

    x-cortex-key: <MCP_ACCESS_KEY>

    If MCP_ACCESS_KEY is not set in .env, the auth check is skipped and the endpoint is open.

    8. Run the Test Suite

    npm test

    Tests live in tests/server/ and use vitest with mocked Ollama and Supabase clients. All tests should pass before making any changes to src/server/lib/ or src/server/routes/mcp.ts.

    Troubleshooting

    Symptom Likely cause Fix
    upsert_entry function not found Migration not applied Run 004_entries.sql in Supabase SQL editor
    vector extension not found pgvector not enabled Run create extension if not exists vector; in SQL editor
    OLLAMA_HOST connection refused Ollama not running ollama serve
    WikiVault directory not found Path not created Run the mkdir commands in step 5
    MCP auth returns 401 Wrong key Check MCP_ACCESS_KEY in .env matches URL param
    Claude Desktop sees no tools Relative paths in config Use absolute paths in claude_desktop_config.json
